接口

端点以发现文档为准。下表路径都在 {{ISSUER}} 下。

用途方法路径说明
发现文档GET/.well-known/oauth-authorization-server授权、令牌、撤销端点和支持的参数
授权GET/oauth/authorize浏览器跳转；带 PKCE 与 state
换取令牌POST/oauth/token服务端调用；client_secret_basic 或 client_secret_post。access_token 5 分钟有效，不发 refresh_token
撤销令牌POST/oauth/revoke用户退出时调用；同样要带客户端认证
资源说明GET/.well-known/oauth-protected-resource/partner/tge受保护资源的元数据
用户身份GET/partner/tge/me需要 tge:identity；返回用户编号 sub。令牌放在 Authorization: Bearer 头里
用户状态GET/partner/tge/status需要 tge:status；账户状态、注册时间、是否已绑定钱包

要点

  • PKCE 必须用 S256。code_verifier 为 43 到 128 个字符（字母、数字和 . _ ~ -），code_challenge 为其 SHA-256 的 base64url，不加填充。
  • state 必填，长度 22 到 512。由你们生成并绑定本次浏览器会话；回调回来后先比对 state，再换码。
  • scope 用 tge:identity tge:status。不带 scope 时只有 tge:identity，调用 /partner/tge/status 会被拒绝。
  • redirect_uri 必须和登记值逐字节相同，包括结尾斜杠和查询参数；换码时也要带同一个 redirect_uri。授权时不一致，返回 HTTP 400 页面，不会跳回你们的地址。
  • 换码在你们服务器上做。用 client_secret_basic 或 client_secret_post，二选一。授权码只能用一次，60 秒内有效；拿到后立即换码。从跳转授权到用户同意，整个登录请求 10 分钟内有效。
  • 同一个授权码不要重试。重复使用会被拒绝，并撤销用它换到的令牌。换码请求请设置足够长的超时（建议 10 秒以上）。
  • 回调参数是 code、state 和 iss。iss 等于上面的 issuer，可用来确认授权方。
  • 如果你们的测试站用自签证书，测试同学的浏览器需要先信任它的 CA，否则跳回时会被拦下。
